Test Case:
LILP-TC-T02-006

Family:
T02 — Identity Continuity

Run Class:
ADVERSARIAL

Title:
Canonicalisation representation completeness

Objective:
Establish that every representation detail capable of changing byte identity is explicitly defined by the declared canonicalisation procedure.

Expected Behaviour:
The procedure explicitly defines the treatment of every applicable byte-producing representation dimension and equivalent logical input produces reproducible canonical bytes.

Failure Oracle:
FAIL if an applicable byte-producing representation detail is materially undefined or produces non-reproducible canonical bytes without an explicit rule.

----------------------------------------------------------------------
Test Case:
LILP-TC-T05-006

Family:
T05 — Evidence Admissibility

Run Class:
CONTROL

Title:
Independent evidence-package re-hashability

Objective:
Establish that the evidence package can be independently re-hashed from the preserved package material using its declared hashing procedure.

Expected Behaviour:
The independently recomputed digest matches the recorded digest for the same preserved byte sequence.

Failure Oracle:
FAIL if the package cannot be independently re-hashed from preserved material or the recomputed digest does not match the recorded digest.

----------------------------------------------------------------------
Test Case:
LILP-TC-T05-007

Family:
T05 — Evidence Admissibility

Run Class:
FAILURE

Title:
Evidence absence does not establish the opposite proposition

Objective:
Falsify unsupported inversion from absence of evidence for one proposition into evidence for its opposite.

Expected Behaviour:
P remains NOT_ESTABLISHED as applicable, and not-P is not established solely from the absence of evidence for P unless a separately applicable inference method independently supports it.

Failure Oracle:
FAIL if absence of evidence for P is treated by itself as positive evidence establishing not-P.

----------------------------------------------------------------------
Test Case:
LILP-TC-T12-006

Family:
T12 — Receipt / Witness Continuity

Run Class:
ADVERSARIAL

Title:
Receipt identifier collision protection

Objective:
Establish identifier uniqueness and prevent silent replacement of an existing receipt under the same declared receipt identifier.

Expected Behaviour:
The tooling refuses the collision, creates a separately identifiable successor where explicitly allowed, or otherwise records the conflict without altering the existing receipt under that identifier.

Failure Oracle:
FAIL if two materially distinct receipts are silently treated as one identifier or if the original receipt is silently replaced under the existing identifier.

----------------------------------------------------------------------
Test Case:
LILP-TC-T16-006

Family:
T16 — Claim-Ceiling Enforcement

Run Class:
CONTROL

Title:
Independent-verification claim prerequisites are explicit

Objective:
Establish that an independent-verification claim identifies the verifier, states the verified scope and discloses material relationships or conflicts capable of affecting the claimed independence.

Expected Behaviour:
The independent-verification claim preserves an identifiable verifier, explicit bounded scope and applicable relationship or conflict disclosures; otherwise the independence claim remains unsupported or bounded accordingly.

Failure Oracle:
FAIL if independent verification is positively represented while the verifier is unidentifiable, scope is materially unspecified, or a known material relationship affecting independence is concealed.

----------------------------------------------------------------------
Test Case:
LILP-TC-T16-007

Family:
T16 — Claim-Ceiling Enforcement

Run Class:
CONTROL

Title:
Claimed-profile requirements-matrix completeness

Objective:
Establish that every normative requirement identifier in a claimed conformance profile is represented in the requirements matrix.

Expected Behaviour:
Every normative requirement identifier in the claimed profile is represented exactly as required by the matrix model; missing mandatory identifiers remain visible as a completeness failure rather than being omitted.
