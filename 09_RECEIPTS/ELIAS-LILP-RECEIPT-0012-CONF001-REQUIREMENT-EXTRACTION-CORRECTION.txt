DEFICIENCY
======================================================================

The original requirement extractor bounded each requirement from its
identifier to the next requirement identifier.

For requirements located at the end of a structural section, this
allowed following section headings, explanatory text, semantic models,
test definitions or other non-requirement content to enter the
RequirementText field.

A later first correction audit used the first blank line as the
requirement boundary.

That audit was also defective because the frozen standard places a
blank line between each requirement identifier and its normative body.

That audit therefore reduced requirement blocks to identifier-only
content and produced a false STRUCTURALLY_ADMISSIBLE result.

The identifier-only audit was not used to modify any artifact.

A second boundary-aware audit used the earlier of:

- the next requirement identifier;
- a structural divider;
- or end of source.

That audit established:

191 unique requirement blocks

0 missing bodies

0 multiple-requirement-ID blocks

0 structural leaks

167 predecessor requirement texts already correct

24 predecessor requirement texts contaminated by following structural
content
