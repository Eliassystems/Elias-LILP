======================================================================
1. PURPOSE
======================================================================

The purpose of SCHEMA-001 is to provide machine-readable structural
contracts for LILP governance objects.

The schema package is intended to support:

- object validation;
- implementation consistency;
- deterministic field representation;
- test-harness construction;
- evidence-package validation;
- receipt validation;
- inter-system examination;
- and bounded reproducibility.

Schema validity does not itself establish semantic truth.

Schema validity does not itself establish authority.

Schema validity does not itself establish conformance.

======================================================================
2. SCHEMA AUTHORITY BOUNDARY
======================================================================

A schema answers questions such as:

"Does this object contain the required structural fields?"

A schema does not, by itself, answer questions such as:

"Is this authority genuine?"

"Is this evidence true?"

"Is this actor authorised?"

"Did the consequence actually occur?"

Those require evidence and governance determination.

STRUCTURAL VALIDITY DOES NOT EQUAL GOVERNANCE VALIDITY.

conformance by any external standards organisation.

======================================================================
6. HASHING RULE
======================================================================

Where an object claims cryptographic identity:

1. identify the declared canonicalisation profile;

2. exclude the object's self-digest field from its own digest input
   unless a separate non-circular construction is explicitly defined;

3. canonicalise the remaining object;

4. encode using the declared encoding;

5. calculate the declared digest;

6. store the digest together with its algorithm identity.

Example:

hash_algorithm:
SHA-256

object_hash:
<digest>

A matching digest establishes byte identity under the declared
canonicalisation procedure.

It does not establish truth.

======================================================================
7. THREE-STATE GOVERNANCE VALUES
======================================================================

Where an evidentiary predicate cannot legitimately be reduced to
Boolean TRUE or FALSE, schema representations should support:

ESTABLISHED

FAILED

NOT_ESTABLISHED

These values are semantically distinct.

NOT_ESTABLISHED does not automatically mean FALSE.

FAILED does not automatically mean NOT_ESTABLISHED.

======================================================================
8. DETERMINATION VALUES
======================================================================

The principal governance determination values are:

ALLOW

HOLD

DENY

ESCALATE

Structural outcomes may additionally include:

NOT_ESTABLISHED

INVALID

NEW_CHAIN_REQUIRED

Schema representations shall preserve the distinction between a
governance determination and a structural state.

======================================================================
9. EXECUTION AND CONSEQUENCE SEPARATION
======================================================================

Machine-readable representations shall preserve separate fields or
objects for:

determination

gate result

execution status

consequence status

This prevents:

ALLOW

from being treated as:

EXECUTED

and prevents:

EXECUTION_ATTEMPTED

from being treated as:

CONSEQUENCE_OBSERVED

======================================================================
10. SUCCESSOR DISCIPLINE
======================================================================

A schema revision shall not silently redefine the meaning of a frozen
predecessor object.

Material schema changes shall use:

new schema version

and where required:

new object version
new successor object
new receipt
new evidence chain

Frozen predecessors remain historical evidence.
